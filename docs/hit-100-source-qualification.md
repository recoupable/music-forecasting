# HIT-100 source qualification

Verified November 26, 2026. This audit describes source coverage and missing evidence. It contains no vendor series or chart rows.

| Input | Evidence | Use |
| --- | --- | --- |
| Hot 100 history | An audit of the community snapshot found 522 consecutive editions with all 100 ranks from 2016–2025. From the first 1958 edition through November 21, 2026, it found 3,564 editions, thirteen with a missing rank, and a 12-day issue-date interval between 1961 and 1962. | Stage as an outcome cross-check. Verify rank gaps, chart entity identifiers, publication dates, and applicable use rights before certifying a benchmark. |
| Independent releases | A MusicBrainz search returned 5,015 official US/worldwide digital release editions for May 3–9, 2024. The first 100 represented 654 track slots before recording deduplication. A separate full version of *Radical Optimism* yielded 11 recording IDs and at least one ISRC per recording. An exact title and artist check against the archive matched three; eight had no exact match and require entity resolution before labeling. | Build a bounded technical cohort sampled by release week and release group, then verify a contemporaneous source for availability. This is a community-catalog sample. |
| Songstats | Four targeted release-window queries, including two no-exact-match album tracks, each returned 31 Spotify history rows with cumulative streams and popularity. The samples had an observation date and no first-publication or revision timestamp. | Use as a feature candidate and capacity test. Ask for date semantics and as-published vintages before treating the series as point-in-time. |
| Recoup | Track measurements returned 404 for the first sample. Its ISRC-based Spotify historic route returned an empty series while Songstats returned 31 dates for the same request. The route reads Recoup's measurement store and can queue historical backfill on a miss. | Use Recoup's measurement API for existing captures and future collection. Inspect the store before triggering any cohort-wide backfill. |

## Fastest path to a defensible first run

1. **Build the chart side immediately.** Run the rank audit, and compare the 2023–2025 pilot period with the official source. Luminate's documented chart catalog accepts `location=US&chart_owner=billboard` and returns chart IDs and earliest available weeks. Request the Hot 100 export or data share, including stable Billboard/Luminate entity IDs, the ISRC-to-entity crosswalk, earliest prior entry or complete prior history, original online publication, and corrections. The issue date alone is insufficient. For example, Billboard reported the April 27, 2024 Hot 100 debut of “Espresso” in an article that says the dated chart would update online on April 23. Establish a single publication rule and use it for eligibility, training maturity, and labels. [Luminate chart catalog](https://docs.luminatedata.com/reference/get-charts) · [Luminate chart data share](https://docs.luminatedata.com/docs/charts) · [Billboard timing example](https://ca.billboard.com/music/chart-beat/sweet-success-hozier-hits-no-1-on-billboard-hot-100-for-first-time)
2. **Build the release side separately.** Use MusicBrainz core recording and ISRC data for a low-friction sample and crosswalk. For the benchmark cohort, request a dated U.S. digital delivery and availability feed from an approved distributor or label first, or the Luminate recording reference export if its coverage includes releases with negligible or no activity. Get all delivered originals in the date window, including withdrawn releases and those with no plays. Request effective date, territory, delivery/first-seen timestamps, ISRC, UPC, artist and title, version, takedown, and lineage. Freeze inclusion before joining chart results. Keep an unclear title or unmatched chart identity unresolved until reviewed. [MusicBrainz core downloads](https://musicbrainz.org/doc/MusicBrainz_Database/Download) · [Luminate recording release definitions](https://support.luminatedata.com/portal/en/kb/articles/song-dashboards)
3. **Qualify Songstats on the independent sample.** Start with one platform and 100–200 recordings sampled by release week and provider, with selection independent of chart performance. Report identifier resolution and same-window feature coverage, then break down missingness by outcome. Confirm existing entitlement and quota for internal research, derivative reporting, and retention. Ask whether the historical response represents first-seen daily observations or a restated series. Require first-seen timestamps or retain the series for a separately versioned exploratory analysis. A cumulative counter needs dated deltas with reset/gap handling. [Songstats data collection coverage](https://developers.stats.company/songstats)
4. **Run the smallest honest baseline.** Build the first panel on an independently defined, bounded cohort with at least 100 eligible recordings per cutoff and enough chart entrants for a useful comparison. Hold out chronological weeks and require complete 90-day label maturity. Benchmark a metadata-only model if performance vintages are still pending, then add Recoup/Songstats as an ablation on the same panel. Run the source qualification without audio. [Benchmark input contract](benchmark-inputs.md)

Chart archive and historical series may be useful privately before publication is cleared. Keep restricted source files out of Git and publish aggregates only when permitted. The source audit checks rank structure. It does not certify original publication timestamps, identify Billboard's track groups, or infer that every absence is a negative.

## Reproduce the chart coverage audit

```sh
mkdir -p .forecast
curl -fsSL https://raw.githubusercontent.com/mhollingshead/billboard-hot-100/main/all.json -o .forecast/hot100-all.json
python -m forecasting.chart_audit .forecast/hot100-all.json --start 2016-01-01 --through 2025-12-31
```

The recorded snapshot SHA-256 was `8d5039cb7519697bbb9d58eb4c8afe641058ba6114a36c6d2da58e0e41c76078`. The upstream snapshot changes as editions are added.
